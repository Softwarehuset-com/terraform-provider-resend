# resend_domain_verification

Triggers verification of a Resend domain.

By default (`wait_until_verified = false`) the resource calls the verify endpoint once, records the current status, and returns. Nothing waits. The status settles to `verified` on later refreshes. This is what you want in CI: a domain whose records are still propagating no longer fails the apply for half an hour.

With `wait_until_verified = true` the create blocks until the domain reaches `verified` or `partially_verified`, bounded by `timeouts.create` (default 30m). If the timeout hits, the error names every DNS record still not passing, like `resend._domainkey.auto (TXT): pending`.

## How Resend verification works

Two facts drive this resource's behavior:

- Resend re-checks a domain's DNS records only when the verify endpoint is called. Reading the domain afterwards returns the stored result, so polling the status alone never flips a `pending` domain. While waiting, the provider re-triggers verify every 60 seconds.
- DNS caches negative answers. If Resend checks a record before it exists, the "not found" answer is cached by the authoritative servers (Cloudflare caches it for 30 minutes), and even a correct record stays invisible until that cache expires. This is the usual reason a verification with correct records still times out: the check ran too early, and no amount of re-verifying sees through the cached miss.

Practical consequence: create the DNS records before verification runs. Point this resource's `depends_on` at the DNS resources built from `resend_domain.records`, and expect a domain registered and verified in the same apply to need up to one negative-cache window before it verifies.

## Example Usage

```terraform
# Trigger a DNS re-check for the domain. Default behaviour: the verify
# endpoint is called once, the current status is recorded, and the apply
# moves on. A slow DNS propagation never fails the apply; the status
# settles to "verified" on later refreshes.
resource "resend_domain_verification" "inbound" {
  domain_id = resend_domain.inbound.id

  depends_on = [cloudflare_record.resend]
}

# Strict variant: fail the apply unless the domain verifies within 10m.
# While waiting, the provider re-triggers Resend's verify endpoint every
# 60 seconds, because Resend only re-checks DNS records when verify is
# called.
#
# resource "resend_domain_verification" "inbound" {
#   domain_id           = resend_domain.inbound.id
#   wait_until_verified = true
#
#   timeouts = {
#     create = "10m"
#   }
#
#   depends_on = [cloudflare_record.resend]
# }
```

## Schema

### Required

- `domain_id` (String) ID of the resend_domain to verify. The verification resource's ID equals this value.

### Optional

- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))
- `wait_until_verified` (Boolean) Wait (poll) until the domain reaches verified before apply completes. Default false: verification is triggered once and the resource is created with the current status; it converges to verified via refresh. Changing this forces re-running verification.

### Read-Only

- `status` (String) Current domain status at last trigger/refresh: pending, verified, partially_verified, not_started or failed. With wait_until_verified = true the create only completes on verified/partially_verified.
